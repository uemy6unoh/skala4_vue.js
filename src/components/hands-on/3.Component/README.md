# Hands-on 3 - Component

Composition 실습에서 만든 날씨 화면을 역할에 따라 여러 컴포넌트로 나눴습니다. 화면의 기능은 유지하면서 부모가 데이터를 관리하고 자식은 전달받은 내용을 표시하거나 이벤트를 알려주는 구조를 연습했습니다.

## 기본 요구사항

### 부모 컴포넌트

WeatherParent에서 날씨 배열과 검색어, 선택한 도시, 날씨 필터 상태를 관리했습니다. 검색 결과를 만드는 computed와 상태 변화를 확인하는 watch, watchEffect도 부모에 유지했습니다.

검색 결과와 선택 문구처럼 여러 자식이 함께 사용하는 값은 부모가 가지고 있어야 데이터가 흩어지지 않는다는 점을 확인했습니다.

### 공통 카드와 slot

BaseDashboardCard는 검색 영역과 날씨 목록 영역에서 반복되는 배경, 테두리, 여백을 담당합니다. 내부에는 slot만 두고 실제 내용은 WeatherParent에서 전달했습니다.

같은 틀을 재사용하지만 안쪽 내용은 서로 다르게 넣을 수 있어서 검색 영역과 목록 영역을 같은 디자인으로 정리할 수 있었습니다.

### 검색창의 props와 emits

SearchBar는 부모의 searchQuery와 검색 결과 문구를 props로 전달받아 표시합니다. 입력이 발생하면 update-query 이벤트와 입력값을 부모에게 전달합니다.

자식이 props를 직접 바꾸지 않고 변경 요청을 이벤트로 올리면, 실제 상태 변경은 부모가 담당하게 됩니다.

### 날씨 카드의 props와 emits

WeatherCard는 도시 객체를 cityItem이라는 props로 전달받습니다. 카드 선택은 select-card, 상세보기는 click-detail 이벤트로 부모에게 알립니다.

상세보기 버튼에는 stop 수식어를 적용해서 버튼을 눌렀을 때 카드 선택 이벤트까지 함께 실행되지 않도록 했습니다.

### 컴포넌트별 스타일

각 파일에서 담당하는 화면의 스타일을 style scoped로 분리했습니다. 카드 모양은 WeatherCard, 검색창은 SearchBar, 공통 박스는 BaseDashboardCard가 각각 관리합니다.

## 추가 사항

### 날씨 필터 컴포넌트

Composition 실습에서 추가했던 날씨 필터를 WeatherFilter로 따로 분리했습니다. 선택 가능한 날씨 배열과 현재 선택값은 props로 받고, 버튼을 누르면 select-weather 이벤트를 부모에게 전달합니다.

직접 추가한 기능도 같은 방식으로 분리해 보면서 props는 부모에서 자식으로 값을 내려주고 emits는 자식에서 부모로 동작을 알려준다는 흐름을 다시 확인했습니다.

### 검색 결과 문구 전달

검색 결과 개수를 계산하는 작업은 부모의 computed가 맡고, SearchBar는 계산된 문구를 받아서 표시만 하도록 구성했습니다. 계산 책임과 화면 표시 책임을 나누려고 한 부분입니다.

## 문제 해결

### 자식에서 부모의 검색어를 변경하는 방법

SearchBar에서 전달받은 currentQuery는 props이므로 자식이 직접 변경할 수 없습니다. input 이벤트가 발생했을 때 새 값을 update-query 이벤트에 담아 부모로 보냈고, WeatherParent에서 searchQuery를 변경하도록 정리했습니다.

### 상세보기와 카드 선택이 함께 실행되는 문제

상세보기 버튼은 WeatherCard 안에 있기 때문에 클릭 이벤트가 카드까지 올라갈 수 있습니다. click-detail 이벤트를 보내는 버튼에 stop을 적용해 카드의 select-card 이벤트와 분리했습니다.

### 파일을 나눈 뒤 스타일 적용 위치

기존에는 한 파일에 모든 스타일이 있었지만 컴포넌트를 나눈 뒤에는 scoped 스타일이 다른 자식 컴포넌트 내부까지 그대로 적용되지 않았습니다. 각 요소를 실제로 렌더링하는 컴포넌트로 관련 스타일을 옮겼습니다.

## 정리

컴포넌트를 나누는 목적은 파일 수를 늘리는 것이 아니라 각 파일이 맡는 역할을 구분하는 데 있다고 느꼈습니다.

부모는 상태와 계산을 관리하고, 자식은 props로 받은 내용을 표시한 뒤 사용자 동작을 emits로 알려주는 흐름을 기준으로 나누니 데이터가 어디에서 바뀌는지 확인하기 쉬웠습니다.
