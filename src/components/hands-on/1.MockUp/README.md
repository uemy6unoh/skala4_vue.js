# Hands-on 1 - MockUp

> Vue 기본 문법을 이용해 날씨 데이터를 카드 화면으로 구성한 첫 번째 Hands-on입니다.

## 과제 개요

5개 도시의 더미 데이터를 반복 출력하고, 날씨와 수치에 따라 카드의 내용이 달라지도록 만들었습니다.

검색어 입력, 카드 선택, 상세보기 버튼까지 연결하면서 데이터가 바뀌었을 때 Vue가 화면을 어떻게 다시 그리는지 확인했습니다. 문법을 하나씩 따로 연습할 때보다 한 화면 안에서 연결해 보니 각 기능의 역할이 더 잘 구분됐습니다.

## 배운 내용과 적용

| Vue 문법 및 개념 | 어디에 사용했는지 |
|---|---|
| `ref` | 도시 목록, 검색어, 선택된 도시 정보를 화면과 연결되는 데이터로 관리했습니다. |
| 보간법 `{{ }}` | 도시명, 날씨, 기온, 습도, 풍속, 미세먼지와 검색어를 화면에 표시했습니다. |
| `v-for` | `weatherList`에 담긴 5개 도시를 같은 카드 구조로 반복 출력했습니다. |
| `:key` | 각 도시의 `id`를 연결해 Vue가 카드별 데이터를 구분할 수 있게 했습니다. |
| `v-if / v-else-if / v-else` | 날씨 아이콘, 기온 상태, 미세먼지 등급과 생활 안내를 조건별로 나눴습니다. |
| `v-bind` (`:`) | 입력창의 `value`와 날씨에 따라 달라지는 카드 `class`를 바인딩했습니다. |
| `v-on` (`@`) | `@input`으로 검색어를 받고, `@click`으로 카드 선택과 상세보기 동작을 처리했습니다. |
| 인라인 핸들러 | 카드 선택처럼 짧은 처리는 템플릿 안에서 바로 작성했습니다. |
| 메서드 핸들러 | 상세보기는 `showDetail` 함수로 분리하고 도시명과 날씨를 인자로 전달했습니다. |
| 이벤트 수식어 `.stop` | 상세보기 버튼을 눌렀을 때 부모 카드의 클릭까지 같이 실행되지 않도록 했습니다. |
| `<style scoped>` | 작성한 카드 스타일이 다른 Vue 컴포넌트에 영향을 주지 않게 범위를 제한했습니다. |

## Personal Development

기본 데이터에 습도, 풍속, 미세먼지를 추가했습니다. 수치를 더 많이 보여주는 것보다 사용자가 현재 상태를 바로 이해할 수 있게 만드는 쪽으로 화면을 구성했습니다.

| 추가한 부분 | 적용 내용 |
|---|---|
| 생활 지표 | 기온과 함께 습도, 풍속, 미세먼지를 같은 크기의 영역에 배치했습니다. |
| 미세먼지 등급 | 수치에 따라 `좋음`, `보통`, `나쁨`을 표시해 숫자의 의미를 바로 알 수 있게 했습니다. |
| 상황별 안내 | 미세먼지, 강풍, 높은 습도에 따라 마스크 착용이나 환기 같은 안내를 보여줍니다. |
| 날씨 중심 디자인 | 도시명과 날씨 아이콘을 먼저 보이게 하고 맑음·흐림·비에 따라 카드 색상을 바꿨습니다. |
| 클릭 동작 분리 | 카드 선택과 상세보기 버튼이 서로 다른 역할을 하도록 이벤트를 나눴습니다. |

안내 문구는 조건에 따라 여러 개를 동시에 보여주기보다 중요한 내용 하나를 먼저 전달하도록 구성했습니다. 예를 들어 날씨가 맑아도 미세먼지가 높으면 외출하기 좋다는 문구 대신 마스크 안내가 먼저 나옵니다.

## Trouble Shooting

| 문제 | 확인한 내용 | 해결한 방법 |
|---|---|---|
| `v-model`에서 한글이 조합 중 바로 반영되지 않음 | 한글은 자음과 모음이 조합된 뒤 값이 확정되기 때문에 화면 반영이 한 박자 늦게 보일 수 있었습니다. | `:value`와 `@input`을 함께 사용해 입력 중인 `e.target.value`를 바로 반영했습니다. |
| 상세보기 버튼을 누르면 카드 선택도 같이 실행됨 | 버튼의 클릭 이벤트가 부모 카드까지 올라가는 이벤트 버블링 때문이었습니다. | 상세보기 버튼에 `@click.stop`을 적용해 부모 카드로 전달되는 클릭을 막았습니다. |
| 여러 안내 조건을 만족해도 문구가 하나만 표시됨 | `v-if / v-else-if` 묶음은 위에서 먼저 참이 된 조건 하나만 렌더링합니다. | 미세먼지와 강풍처럼 먼저 알려야 할 조건을 위쪽에 배치하고 기본 안내는 마지막 `v-else`에 두었습니다. |

## 마무리

이번 실습에서는 `v-for`, `v-if`, 바인딩과 이벤트가 각각 떨어진 기능이 아니라 데이터와 화면을 연결하는 흐름이라는 점을 확인했습니다. 특히 조건의 순서와 이벤트 버블링처럼 화면만 봐서는 알기 어려운 동작을 직접 수정해 본 부분이 다음 실습에서도 도움이 될 것 같습니다.
